## 1. 分類をやり直す ── 「総額か任意欄か」では足りない

いまコードは費目を2つにしか分けていない。

```
lines[]          → 総額に入る
optionalLines[]  → 総額に入らない。画面で畳む
```

**この2分法が複雑さの原因。**「任意欄」に3種類の別物が同居している:

- 利用者が**選ぶから**総額外（写真・保護梱包）
- 条件で**決まる**が、置き場所を間違えて総額外（輸出通関）
- 条件で決まるが、**入力が無いから**額を出せず総額外（保管料）

後ろ2つは任意費目ではない。**発生の仕方で5つに割る。**

| | 区分 | 意味 | 総額への入れ方 |
|---|---|---|---|
| **A** | **必ず発生** | その注文をすれば常に起きる | 総額に入れる |
| **B** | **条件で決まる・条件は分かっている** | 閾値や仕入先で決まり、**我々は条件を持っている** | **総額に入れて条件判定する。**発生しないときは「出典のある ¥0」 |
| **C** | **条件で決まる・入力が無い** | ルールは分かっているが、入力（日数・寸法・申告額）が画面に無い | **入力を作って総額に入れる。**それまでは区間の上端 |
| **D** | **利用者が選ぶ** | 選ばなければ発生しない | 任意欄。総額外で正しい |
| **E** | **予測不能・管轄外** | 原理的に予測できない、またはモデルの外 | 免責として明示。区間でも当てにいかない |

**B と C を「任意欄」に置いてはいけない。**利用者に費目を探させることになり、
しかも総額が必ず過小に出る。いま B が 1 件・C が 3 件、任意欄に誤配置されている（§3）。

### 金額の効きが最も大きいもの

**F25 の宅配便。**実請求の言及数は FedEx 12 / EMS 11 / UPS 7 / DHL 7 / 船便 3 で、
**発送の約半数が宅配便なのに 0 円を出している。**スペインの同一荷物の見積では
船便 €27 ／ FedEx €40 ／ UPS €55 ／ DHL €61 ／ EMS €63 で、**送料だけで 2.3 倍・差 €36 ≒ ¥5,900。**
これを入れると F28/F40（送料の2〜3割）と F34 の業者軸が同時に必要になる。
