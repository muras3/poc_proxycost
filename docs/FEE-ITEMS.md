## 1. 分類をやり直す ── 「総額か任意欄か」では足りない

いまコードは費目を2つにしか分けていない。

```
lines[]          → 総額に入る
optionalLines[]  → 総額に入らない。画面で畳む
```

**この2分法が複雑さの原因。**「任意欄」に3種類の別物が同居している:

- 利用者が**選ぶから**総額外（写真・保護梱包）
- 条件で**決まる**が、置き場所を間違えて総額外（輸出通関）
- 条件で決まるが、**入力が無いから**額を出せず総額外（保管料）

後ろ2つは任意費目ではない。**発生の仕方で5つに割る。**

| | 区分 | 意味 | 総額への入れ方 |
|---|---|---|---|
| **A** | **必ず発生** | その注文をすれば常に起きる | 総額に入れる |
| **B** | **条件で決まる・条件は分かっている** | 閾値や仕入先で決まり、**我々は条件を持っている** | **総額に入れて条件判定する。**発生しないときは「出典のある ¥0」 |
| **C** | **条件で決まる・入力が無い** | ルールは分かっているが、入力（日数・寸法・申告額）が画面に無い | **入力を作って総額に入れる。**それまでは区間の上端 |
| **D** | **利用者が選ぶ** | 選ばなければ発生しない | 任意欄。総額外で正しい |
| **E** | **予測不能・管轄外** | 原理的に予測できない、またはモデルの外 | 免責として明示。区間でも当てにいかない |

**B と C を「任意欄」に置いてはいけない。**利用者に費目を探させることになり、
しかも総額が必ず過小に出る。いま B が 1 件・C が 3 件、任意欄に誤配置されている（§3）。

### F25〜F30 に着手すると同時に必要になるもの

**F25 に宅配便を入れると3つが付いてくる。切り離せない。**

| | なぜ同時に必要か |
|---|---|
| **F28 / F40** 燃油・遠隔地サーチャージ | FedEx/DHL が週次で公表し**送料の 2〜3 割**。入れないと宅配便だけ 2〜3 割安く出る |
| **F34 の業者軸** | 宅配便は通関経路が郵便と別。スペインの実請求で経路により **€1.56〜€70（45倍）**。郵便の手数料を宅配便に当てると、**送料は下がり通関は上がるという向きが逆の誤りが総額に同居する** |
| **寸法の軸** | 宅配便は容積重量課金。`Item` に寸法が無い（`TODO-NEXT.md` §0b と同じ穴） |

**そして F25〜F30 を終えても総額の正確さは決まらない。**残る2つが上限を決める:

- **F39 申告額ポリシー** ── 5社非公表。F31・F32・F34・F36 の全部がこれに依存する
- **総額が点推定** ── 未取得の費目が 0 に落ちるので、**何を足しても総額は過小側に出続ける**

正しい言い方は「F25〜F30 で総額がまあまあ合う」ではなく
**「F25〜F30 で順位と差額がかなり正確になる」。**総額の正確さは F39 と区間化で決まる。

## 5. リスク登録

**「根拠のある数字」ではなく「我々が置いた判断」を、判断と分かる形で残す節。**
総額が外れたとき、どの判断を疑えばよいかがここで引けることが目的。

各行に **何を置いたか / 外れる条件 / 外れたときの影響**を書く。
`docs/MASTER.md` の `D_unpredictable`（原理的に予測できないもの）とは別で、
**こちらは「決められるが、一次情報が無いので我々が決めた」もの。**

| # | 置いた判断 | 根拠の強さ | 外れる条件 | 外れたときの影響 |
|---|---|---|---|---|
| **R1** | **F13b ── 「送料無料」の出品に国内送料を足さない**（警告だけ出す） | **発生率を持っていない。**Buyee は「送料無料でも追跡便に変更して国内送料を発生させることがある」と公式に警告しているだけで、頻度を書いていない | 実際には高い頻度で発生する | **総額が過小**。最大 ¥800/注文（我々の国内送料の仮定額）。全社に等しくは乗らないので**順位も動きうる** |
| **R2** | **保管日数の既定を 45 日に置く** | **一次情報ではない。**「倉庫に貯めてまとめ発送」という使い方の実態に寄せた我々の仮定 | 利用者が実際には 30 日以内に送る（→ 全社 ¥0 になり、この費目は消える）／60 日を超える（→ ZenMarket・Jauce にも課金が始まる） | **45 日では Buyee だけに ¥1,500〜4,500。**基準ケースの1位2位差 ¥650 を超えるので**順位が動く**。日数を変えると向きごと変わる |
| **R3** | **Neokyo を「商品 45 日」の無料期間で測る** | **原文は2つの期間を並べている**——「45 days for items and **7 days for packages**」。どちらで測るかは書かれていない。貯めている対象は商品なので商品側を採った | 利用者が実際には**梱包済みの荷物**を置いている | **¥0 か ¥2,100 の差**（7 日で測ると 38 日超過 = 6 週 × ¥350。寸法が大きければ週 ¥980 まで上がる）。**Buyee の ¥1,500 と同じ桁なので順位が変わる** |

### 画面での扱い

- **R2 / R3 は `tier: estimate`** ── 我々の判断なので確定色にしない
- **日数は利用者が変更できる欄にする。**変えたら即座に再計算・再ランキングする
- **R3 は Neokyo の保管行の note に「荷物として置く場合は無料期間が 7 日で、額はこれより高くなる」と書く。**
  書かなければ、荷物側で課金される利用者に対して黙って過小に出すことになる

### この節に足す基準

**「一次情報が取れなかったので我々が決めた」もの全部。**
逆に、一次情報で確定したものは書かない（それは `master/fees.json` の `tier: A_confirmed` の領域）。
原理的に予測できないものも書かない（それは `docs/MASTER.md` の `D_unpredictable`）。
