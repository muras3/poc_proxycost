# 設計上の制約（実装前のメモ）

## 1. 総額の 84% は公表額。**順位は推論に対して頑健ではない**

**2026-09-07 実測**（5点 × ¥3,000・600g/点・ヤフオク、7カ国それぞれの1位の行、
合計 ¥263,981。任意費目を除く）:

| 確度 | 額 | 割合 |
|---|---:|---:|
| 公表の料金表（`fixed`） | ¥221,079 | **84%** |
| 推定（`estimate`） | ¥37,974 | 14% |
| 二次情報（`unverified`） | ¥4,928 | 2% |

国別の `fixed` の割合：US 84% / GB 86% / DE 81% / FR 84% / AU 88% / CA 83% / SG 79%。
米国の内訳は `src/app/sources/measured.ts` の `CONFIDENCE_SPLIT`
（fixed ¥30,250 / estimate ¥4,000 / unverified ¥1,875）が持っていて、
`measured.test.ts` が毎回 `compare()` で測り直す。

### 「総額の約半分が推論」は 2026-09-06 の値（否定された）

以前ここには次の表と「**総額の約半分が推論。**英国では 59% / 37% / 4%」が書いてあった
（5点 × ¥3,000・600g/点・米国、1位 Neokyo ¥37,586）:

| | 金額 | 割合 |
|---|---:|---:|
| 金額も発生も確定（商品代・代行手数料・梱包） | ¥17,550 | 47% |
| 発生は確定・金額は推定（国内送料 ¥4,000・国際送料 ¥12,700） | ¥16,700 | 44% |
| 二次情報（米国関税 12.5% ¥1,875・USPS $9.35 ¥1,461） | ¥3,336 | 9% |

**推論側が減ったのは総額が良くなったからで、基準を緩めたからではない。**動いたのは2つ:
国際送料 ¥12,700 は EMS の公表額そのもので、推定なのは**引くのに使う重量のほう**だと
分けた（`docs/COMPLETENESS.md` T16。重量の推定は `Row.approximate` が別に数える）。
USPS $9.35 は無条件加算をやめ、前払い帯では**取得できた 0** になった
（`docs/TODO-NEXT.md` §3）。**いま推論なのは半分ではなく 16%。**

### 順位の頑健性の主張は実測で否定された（2026-09-06）

以前ここには「重量を ×1/10 から ×3 まで外しても1位は動かない」「総額が 46% ずれても
順位は1つも動かない」と書いてあった。**費目を一次情報に直したあとの再測定で、これは
成立しないことが分かった。**（旧測定は EMS 表の丸めと、実在しない費目・存在しない
「Neokyo は国内送料込み」を前提にしていた。）

1位が入れ替わる重量（米国・¥3,000/点・ヤフオク・国内送料あり、25g 刻みで走査）：

| 点数 | 1位が入れ替わる重量 |
|---|---|
| 1点 | **交差なし。**FROM JAPAN が 25g〜24,750g のどこでも1位 |
| 2点 | **1,150g** で Neokyo → FROM JAPAN |
| 3点 | **1,325g** で Neokyo → FROM JAPAN |
| 5点 | **1,625g** で Neokyo → FROM JAPAN。さらに **4,975g** で比較可能な行が Buyee default だけになる |

交差点は 1〜2kg にある。代行で買う品物としてごく普通の重量帯であり、
重量表の推定誤差が容易に跨ぐ幅である。5点 × 600g（既定の推定値）では
**GB・DE・FR・CA の4カ国で `rankStable=false`**（US・AU・SG の3カ国は `true`——US は
FROM JAPAN、AU と SG は Neokyo が最安のまま動かない）。

**ここには以前「7カ国すべてで `rankStable=false`」と書いていたが、これは間違いだった。**
`CONFIDENCE_SPLIT` や `WEIGHT_SHIFT` と同じく `compare()` で測り直してテストで縛る仕掛けを
`rankStable` にも作っていなかったため、2026-09-06 以降の費目修正（Neokyo の国内送料・
FROM JAPAN の ¥200・ZenMarket のサイト別・輸出通関の総額化）で値が動いたのに、この行だけ
誰も測り直していなかった。いまは `src/app/sources/measured.ts` の `RANK_STABILITY` が
7カ国分を持ち、`measured.test.ts` が縛る。

5点 × ¥3,000・米国の実測（`docs/audit/measured-2026-09-06.md`）。この表と `/sources` の同じ表は `src/app/sources/measured.ts` の1か所から来ていて、`src/app/sources/measured.test.ts` が毎回 `compare()` で測り直して突き合わせる。**手で書いた総額は腐る。**為替を ECB へ直したとき（4186822）この表を直し忘れ、公開ページが ¥58 古い総額を実測として出していた：

| 実重量/点（5点） | 1位 | 総額 | 2位との差 | 最下位 |
|---:|---|---:|---:|---|
| 200g | Neokyo | ¥31,186 | ¥1,250 | Buyee, default ¥54,080 |
| 600g（推定値） | Neokyo | ¥37,586 | ¥950 | Buyee, default ¥63,130 |
| 1,500g | Neokyo | ¥52,886 | **¥50（0.1%）** | Buyee, default ¥78,680 |
| 3,000g | **FROM JAPAN** | ¥74,536 | ¥1,300 | Buyee, default ¥96,680 |

**2026-09-07 追記: この表の総額は 2026-09-06 の値で、`measured.ts` はもう別の値を持っている。**
米国の通関手数料 $9.35 が前払い帯では立たないと分かって落ちたため（`docs/TODO-NEXT.md` §3）、
現在の `WEIGHT_SHIFT` は 200g ¥29,725 / 600g ¥36,125 / 1,500g ¥51,425 / 3,000g ¥73,075。
**1位と最下位の顔ぶれは変わらない**（`measured.ts` が正で、この表は手書きのまま腐った——
上の「手で書いた総額は腐る」がそのまま起きた）。

600g を基準に ×1/3（200g）で総額は −17%、×3（1,800g）で +54% 動き、**×3 の側では
1位が FROM JAPAN に替わる。**総額の誤差が全社に等しく乗るという以前の説明は、
重量に非線形に効く費目（Neokyo の梱包 ¥500+¥150/kg、EMS の段、Buyee の個口分割）を
無視していた。

実装の `rankStable` は ×1/3 と ×3 の2点で判定する（`src/lib/pricing/compare.ts`）。
それ以上振らないのは、梱包後の重量が EMS 公表表（30kg）を出ると「順位が変わる」ではなく
**「比べられなくなる」**ため。判定できない倍率は「動いた」とは数えない。

### 表の外に出るとき

5点では **4,950g/点**（梱包後 30.0kg）までが公表表の中。これを超えると1個口にまとめる
4社は国際送料を出せず、`comparable:false` になって順位から外れる。注文ごとに分ける
Buyee default だけが表の内側に残り、唯一の比較可能な行として1位になる。
このとき**比較不能な行の総額は1位より安く見える**（最大の費目が欠けているため）が、
順位には出さないし最安にもしない。

> 以前この節には 3,000g/点で「総額を出せない」と書いてあったが、**それは EMS 表を
> 27段（15kg）までしか転記していなかったからで、公表は 42段・30kg まである。**
> さらにその前は 18.3kg を 15kg の料金に丸めて ¥62,178 と書いていた。
> どちらも 2026-09-06 の敵対的監査で発覚し、同日修正した。

### UI への帰結

**現在の素案は強調が逆になっている。**最大の文字が総額（最も不確かな数字）で、
順位と差額（最も確かな情報）が小さい。

画面の主役は **順位と差額**、総額は概算として添える。その場で決めるのは「どれを選ぶか」で、
差額のほうが総額より確かだから。**これは総額の精度を諦める話ではない**——プロダクトの定義は
「総額を可能な限り正確に出して順位づけする」であり（REQUIREMENTS §2）、総額はその**順位の
入力そのもの**なので、精度は最後まで上げる。強調の大小と、数字を作り込む優先度は別のこと。
ただし順位も重量次第で動く以上、`rankStable` と `rankStabilityNote` を隠さずに出し、
不安定なときは「重量の推定が外れると1位が替わる」と書く。**「概ね頑健」とは書かない。**

**重量は利用者に直してもらう（2026-09-06）。** 重量表 69 ラインのうち 14 ラインで
P25–P75 が上の交差点を跨ぐ（kpop/photobook 800–1,600 g n=1,182、sports-goods/hakama
1,500–2,500 g n=1,696、kendo-do 1,500–7,500 g n=97、kpop/magazine 1,200–2,500 g n=542）。
サンプルを増やしても縮まらない — 品ごとに本当に違う。だから推定の精度では解決せず、
入力してもらうしかない。ただし全員に強制はしない: 推定値（表の中央値、当たらなければ
1,000 g の仮置き）を既定で入れ、その場で直せる欄にする。`compare()` は 1点ずつ
「その品の重量だけを P25–P75（仮置きは 500 g〜10 kg）で動かすと1位が替わるか」
（`weightSensitivity`）を返し、替わる品だけを画面が名指しする。既定の2点に表に無い品を
1点足すと、仮置き品だけでなく**ねんどろいど（380–600 g）も1位を決める品になる**一方、
単独1点は 500 g〜10 kg のどこでも FROM JAPAN で、聞く必要が無い。設計の全文は
docs/UI-DESIGN.md §4。

### 逆転条件

**「送料込み出品だと1位が Neokyo から FROM JAPAN に替わる」も成立しない。**
Neokyo のサービス料に国内送料は含まれない（公式の料金ページは「商品代＋国内送料」に
¥350 を足す形。2026-09-06 の監査 fees.md で修正）。いま5社とも国内送料は別建てなので、
送料込み出品は**全社に等しく効き、1位は動かない**。
7カ国 × 1/2/3/5点 × 200〜3,000g で実測し、`freeShipping` の有無で1位が変わった組み合わせは
1つも無かった。

動くのは順位の中位だけで、**送金合計額に率で乗る費目を持つ社**（ZenMarket の入金手数料
3.5%）が、国内送料が消えた分だけ相対的に得をする。5点 × 200g・米国では ZenMarket が
4位から3位へ上がる（Buyee, consolidated と入れ替わる）。1位が動く条件は、いまのところ
**重量**（上記の交差点）と**個口の分け方**の2つだけ。

## 2. 費目は2軸で分類する

| | 必ず発生 | 条件付き・任意 |
|---|---|---|
| 金額が確定 | 商品代／代行手数料／国内配送サービス料／入金手数料 3.5% | Buyee 保護梱包 ¥1,500・特殊梱包 ¥2,500・通関手数料 ¥2,800・保管延長 ¥100〜300/日／Neokyo 開梱 ¥1,000・コンビニ ¥1,000／ZenMarket 写真 ¥500・再梱包 ¥1,000〜4,000／保証プラン |
| 金額が推定 | 国内送料 ¥150〜1,500／国際送料（重量次第）／VAT（課税ベースが送料に依存） | 梱包の重量加算 |
| 二次情報 | 米国関税 12.5%（**下限。カテゴリ次第で税率そのものになる**）／USPS $9.35／Royal Mail £8 | FROM JAPAN の手数料体系（定額か率か不明） |
| 取得できていない | — | 米国以外の閾値超関税／独仏星の通関手数料／カード為替手数料／英国の酒税の額（ABV が要る） |

> **カナダの州税は 2026-09-07 にこの行から出た（T23）。**CBSA の Memorandum D2-3-6
> Appendix A（輸入品に対する州税の徴収表）を取り、州を選べるようにした。州を選ばない
> ままでも `—` にはしない——発生が確実なので、人口加重の代表値（7.3%）を tier estimate で
> 出す。同じコミットで Canada Post の CAN$9.95（「per dutiable or taxable mail item」）も
> 通関手数料の行に入った。残るカナダの未取得は関税率だけ（品目分類が要る）。

「金額は確定だが発生が不確実」（特殊梱包）と「発生は確定だが金額が不確実」（国際送料）は
性質が逆なので、画面上の扱いも分ける。既定は最小構成で計算し、任意の費目は
「これを選ぶと +¥1,500」として別に見せる。

## 3. 検証済みの一致

ZenMarket の入金手数料は「送金合計額の 3.5%」。¥10,000 をチャージするには
`10000 / (1 - 0.035) = ¥10,362.7` が必要になる。台湾の利用者が公開した実際の請求は
**¥10,363**。実請求と 1 円差で一致した。
