## 1. 何を取ろうとして、何が起きたか（社ごと）

### ZenMarket（優先1・呼び口が判明していた社）

- `robots.txt` を確認: `/calc.aspx` 自体は許可対象（Disallow は `/en/en/` 等の言語重複パスのみ）。`Crawl-delay` の明示なし
- 実測: `POST https://zenmarket.jp/calc.aspx/Calculate` に `{"weight":"600","country":"DE","width":"20","height":"15","depth":"10","totalPrice":""}` を1回投げた
- **応答が HTTP 403 で、本文は Cloudflare の「Just a moment...」チャレンジページ**
  （`challenges.cloudflare.com` を読み込むJSチャレンジ＝CAPTCHA相当）
- `AGENTS.md` / `O2-COURIER-RUN.md` の「CAPTCHA が出たら止めろ。回避を試みるな」に従い、
  **この1回の応答確認をもって停止。リトライもヘッダ偽装の試行もしていない**
- 前回の監査（2026-09-08）の時点ではこの保護は無かったとみられる
  （前回の作業者は同じエンドポイントに1.5秒間隔で複数回到達し、実測値を得ている）。
  **2026-09-08〜2026-09-11の間にZenMarket側がCloudflare保護を追加した可能性が高いが、確証はない**
- **観測値0件。便IDの対応表・決定実験（compact/bulky/blank）・容積走査、いずれも未着手**

### Neokyo（優先2）

- 手順書が記録している呼び口 `https://neokyo.com/en/shipping-rates-estimate?weight=600&country_to=DE`
  は構造上クエリ文字列でしか呼べない。**つまりこの計算機自体がrobots.txtの禁止対象**
- よってリクエストを送らずに対象外と判断した（規約の確認以前の段階で停止）
- **観測値0件**

### Buyee（優先2）

- 「判断が付かなければ止めて報告」に従い、計算機へのリクエストは送っていない

## 2. 容積重量の除数は決まったか

**決まらなかった。** 今回のランでは実測値そのものが1件も取得できていないため、
除数を導く材料（compact/bulky/blankの比較、立方体走査）が存在しない。
「決まらない」こと自体は指示上、失敗として扱わない旨明記されているため、そのまま報告する。

## 3. 前回（2026-09-08、汚染されていた分）と今回で結論は変わったか

**変わらない。** 前回の監査が到達した「日本郵便4方式は実重量課金・寸法に依存しない」
という結論（`docs/audit/o2-courier-2026-09-08.md` §2）には今回一切触れていない
（本作業の指示で「日本郵便には適用しない・現行のまま触るな」と明記されているため対象外）。
宅配便側（FedEx/UPS/DHL等）については前回も今回も**除数・最終価格ともに未確定のまま**であり、
「上乗せ率で価格化する」旧方針から「最終価格をそのまま採る」新方針への切替は済んだが、
**その新方針を実行するための実測データは今回のランでは1件も得られていない。**
したがって `master/fees.json` / `services.ts` に対する変更点は無い。

## 4. 自分の測定の弱点

- **ZenMarketのCAPTCHA/Cloudflareチャレンジは1回の応答のみで判断した。**
  時間帯やIP、リクエストヘッダ（User-Agent等）によって挙動が変わる可能性があり、
  「常に保護されている」と断定はできない。ヘッダを変えたりリトライ間隔を空けて
  再確認すれば通る可能性は否定できないが、本ランでは「CAPTCHAが出たら止める」を
  厳格に適用し、ヘッダ偽装や複数回の試行はしていない
- **Neokyoの `Disallow: /*?*` 判定は、手順書記載のURL形式のみを見た結果。**
  クエリ文字列を使わない別の呼び口（POST APIなど）が存在する可能性は調査していない
- **FROM JAPAN・Jauceは「計算機の場所」そのものを探索していない。**
  301リダイレクト先やDNS/証明書の状態を深追いすれば進展した可能性がある
  （今回は「まず先に読め」の手順に従い外部通信の疎通確認を優先し、
  個々の社の深い探索までは手を伸ばしていない）
- **Buyeeのrobots.txt 403は、通常のブラウザアクセスでも同様かは未確認。**
  自動化ツール（curl相当）からのアクセスに限定してブロックしている可能性があり、
  「規約が自動アクセスを禁じている」とまでは断定できず、「確認不能」と記録するに留めた
- 全体として、**今回のランは『取得手順の実行』ではなく『取得可否の一次確認』で終わっている。**
  5社×多数の組み合わせを取る本来の作業には至っていない
