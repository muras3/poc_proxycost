# 同額（タイ）の実測 — T26 の根拠（2026-09-07）

`compare()` が返す総額が**ちょうど一致する**組み合わせがどれだけ在るか、
そのとき旧実装の第2キー（社名の辞書順）が誰を上に置いていたかを測った。

走査の範囲（188,160 組）:

| 軸 | 値 |
|---|---|
| 宛先 | US / GB / DE / FR / AU / CA / SG（7） |
| 出品サイト | yahoo-auctions / mercari / rakuten（3） |
| 点数 | 1 / 2 / 3 / 5（4） |
| 重量 | 25 g 〜 8,000 g を 25 g 刻み（320） |
| 価格 | ¥1,000 / 3,000 / 4,200 / 5,000 / 12,800 / 30,000 / 50,000（7） |

全点同一価格・同一重量・国内送料は既定の推定（¥800）・重量は `weightOrigin: 'user'`。

## 結果

```
combinations scanned: 188160
combinations with a tie: 3938
combinations where the tie is at rank 1: 15

tie pairs (any rank):
  buyee = neokyo: 3672
  neokyo = zenmarket: 97
  buyee:consolidated = fromjapan: 88
  fromjapan = zenmarket: 37
  buyee = jauce: 34
  buyee:default = jauce: 10

tie pairs (rank 1):
  neokyo = zenmarket: 15
```

**同額は例外ではない。**同額を含む組み合わせが 3,938（走査の 2.1%）在り、
そのうち 15 組は**1位が同額**である。

代表的な入力（テストに固定した2つ）:

| 入力 | 同額になる行 | 総額 | 順位 |
|---|---|---:|---|
| 1点 ¥12,800・1,450 g・ヤフオク・US | Buyee / Neokyo | ¥26,761 | 2位タイ（1位は FROM JAPAN ¥26,461） |
| 1点 ¥4,200・450 g・楽天・AU | Neokyo / ZenMarket | ¥10,420 | **1位タイ** |

## 旧実装の第2キーが誰を上に置いていたか

旧実装は `a.total - b.total || a.serviceName.localeCompare(b.serviceName)`。
同額の 3,938 組で、辞書順が先頭に置いた社の報酬の有無を数えた:

```
{ groups: 3938, paying: 3716, free: 97, neutral: 125 }
```

- **`paying` 3,716 組（94.4%）＝ 報酬を払う社が、報酬ゼロの社より上に置かれていた。**
  ほぼ全部が `buyee = neokyo`（`'Buyee' < 'Neokyo'`）で、Buyee は報酬を払い Neokyo は払わない。
- `free` 97 組 ＝ 逆向き（`'Neokyo' < 'ZenMarket'`）。1位が同額になる 15 組はここに入る。
- `neutral` 125 組 ＝ 両方とも報酬を払う社どうしの同額。

社名の辞書順そのものに意図は無い。しかし**結果は 94% の偏り**で、
「順位は総額だけで決める」（REQUIREMENTS §2）という約束を、並べ替えの第2キーが
事実上破っていた。順位を報酬で決めないという主張は、第1キーだけでは守れない。

## 決めたこと

1. **同額は同順位。**rank は「自分より厳密に安い比較可能な行の数 + 1」（競技順位、1-1-3）。
2. **CHEAPEST は同額の全行に付ける。**「これより安い選択肢は無い」という事実の表明で
   あって1社を推すバッジではないので、事実が2社で成り立つなら2社に付く。
   どちらにも付けない案は「最安が存在しない」と読め、答えを持っているのに黙ることになる。
3. **同順位の行の縦の並びは何も意味しない。**第2キーを消したので並びは `SERVICES` の
   宣言順（安定ソートの残り）になるが、それも根拠ではない。だから画面が
   `tied with … — the order between them means nothing` と、その行の中で打ち消す。
4. 「1位が動いたか」（`rankStable` / `weightSensitivity.decisive` / 段ごとの最安）は
   **集合**で見る。`rows[0]` で見ると、同額の中でどれが先頭に来たかという並びの偶然を
   「順位が動いた」と読んでしまう。基準の重量で最安だった行が1つでも端で最安のままなら、
   選ぶべき社は変わっていない。
