# 監査：キーワード検索が実際に何を返すか

対象ブランチ `claude/automated-income-schemes-uzn8zw-rh3uwh`。検査日 **2026-09-07**。
本番 <https://proxycost.3amoncall.workers.dev> の `/api/search` と `/api/product` を
実際に叩いた実測だけを書く。**推測は書かない。取れなかったものは「取れなかった」と書く。**

エッジのキャッシュを避けるため、全リクエストに `&_cb=<乱数>` を付けた。

---

## 0. 先に結論

**「検索して総額を比べる」という入口は、実測では次の3点で設計どおりに動いていない。**

1. **価格が1件も返らない。** 55 クエリ・1,090 件で `priceYen` が入ったのは **0 件**。
   画面は全カードが `price not shown — you'll enter it` になる。
   `docs/UI-DESIGN.md` §7.4 の絵は 4 枚中 3 枚に `~¥2,800` が入っている。
2. **返ってくるものの 4 割が出品ではない。** 1,090 件中 **471 件**が検索結果ページ・
   カテゴリ・記事。ヤフオクに至っては 192 件中 **189 件**が一覧で、うち多くが
   終了済みの `/closedsearch/`（もう買えない。ヤフオク自身の robots.txt が禁じている）。
3. **URL を貼る逃げ道も半分は塞がっている。** 出品 URL 32 件を `/api/product` に
   通して価格が取れたのは **10 件**。Amazon（検索結果の 4 割を占める）は
   0/4、駿河屋は 403、楽天は 10 秒で返らない。

## 3. `/api/product`（URL を貼る道）の実測

検索で得た出品 URL からサイトごとに無作為に選んだ **32 件**を通した。

| サイト | 試行 | 価格が取れた | 何が起きたか |
|---|---:|---:|---|
| Yahoo! Shopping | 4 | **4** | JSON-LD から読めている |
| Mercari | 4 | 3 | 1 件は JS 描画の外枠だけが返り、題が `メルカリ - 日本最大のフリマサービス` になった |
| Toranoana | 3 | 3 | 読めている |
| Yahoo! Auctions | 2 | **2** | 別途、生きている出品 2 件で確認。題・価格・画像とも取れる |
| Amazon.co.jp | 4 | **0** | 題は取れるが価格が無い。UA `proxycost/0.1` には 3.8 KB の bot 判定ページしか返らない（JSON-LD なし） |
| Suruga-ya | 4 | 0 | **HTTP 403** |
| Rakuten | 4 | 0 | 10 秒で返らない（実測 10.6–11.4 秒）。しかも UA `proxycost/0.1` には WAF の 404 が返る |
| Mandarake | 4 | 0 | 題が `MANDARAKE` になる（商品名が取れていない） |
| HMV Japan | 4 | 0 | 商品名が読めない |
| ZOZOTOWN | 1 | 0 | 接続が返らない |

**ヤフオクだけは、検索では出ないが URL を貼れば完全に動く。**
逆に **Amazon は検索でも URL でも価格が取れない**。検索結果の 4 割がこれである。

## 4. Brave Search API の仕様（公式ドキュメントで確認）

出典: <https://api-dashboard.search.brave.com/app/documentation/web-search/responses>
（SvelteKit の `__data.json` から本文の Markdown を取得。確認日 **2026-09-07**）
と <https://brave.com/search/api/>（料金、同日）。

- **`product` も `thumbnail` も、現在の Web Search のドキュメントに1文字も出てこない。**
  本文全文（14,631 文字）を検索して 0 件。`REQUIREMENTS.md` §8.5 の
  「`thumbnail` と `product.price` はスキーマに存在する」は**現在のドキュメントでは裏が取れない**。
  実測では `thumbnail` は 41% に返ってくるが、`product.price` は 1,090 件で 0 件。
- **`count` は最大 20、`offset` は 0–9**（＝実質 200 件）。次ページを取るなら
  `more_results_available` を見てから、と明記されている。
- **検索演算子として書かれているのは4つだけ**：`"..."`（完全一致）、`-`（除外）、
  `site:`、`filetype:`。**`OR` も括弧も書かれていない。**
  いま `siteFilter()` が投げている `(site:a OR site:b OR ...)` は
  **ドキュメントに無い形**。実測では効いている（1,090 件すべてが対象 10 サイト内）が、
  保証された動作ではない。`/documentation/resources/search-operators` は
  2026-09-07 時点で 404（公開されていない）。**クエリ長や演算子の個数の上限は
  公式には見つからなかった。**
- `extra_snippets=true` で 1 件あたり最大 5 本の追加抜粋が返る（**未使用**）。
- Goggles（再ランク付け）に対応（**未使用**）。
- 料金: **$5 / 1,000 requests、月 $5 のクレジット、50 QPS**。
  **保存の権利について**: 「結果の一部または全部を保存したい場合は、
  保存権を明示的に付与するプランに加入する必要がある」と書かれている。
  いま `src/lib/search/cache.ts` は 24 時間 KV に保存している。
  **`REQUIREMENTS.md` §8.5 の未決事項はまだ未決のまま。**

## 5. この監査で直したこと

- **一覧ページを候補から外した**（`src/lib/search/sites.ts` の `listing` と
  `isListingUrl`、`brave.ts` での絞り込み）。実測 1,090 件のうち 471 件が消え、
  1クエリあたりの候補は中央値 12 件になる。**0 件になるクエリが 55 中 2 つ**
  （`ポケモンカード リザードン` / `同人誌 東方`）出るが、画面は
  「No listings found. Paste a listing URL instead.」に落ちる。
  値段の付かない行が籠に入るより、件数が減る方がまし。
- **貼り付けにも同じ判定を効かせた**（`SearchBox.tsx`）。一覧 URL を貼られたら
  取りに行かずに「1点の出品ページを貼れ」と言う。
