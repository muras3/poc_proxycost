# 遠隔地サーチャージ（F40）はFedEx/DHL/UPSの表示価格に「込み」か ── 2026-09-12監査

## 位置づけ

本文書は F28（燃油サーチャージ）に対する監査
`docs/audit/fuel-surcharge-inclusion-2026-09-12.md`（結論: §5.5 追記、`conclusions.fuel_surcharge_working_treatment`、
id `C11_fuel_working_treatment_2026_09_12`）と対になる。**F40（遠隔地／配達地域サーチャージ）に
ついて、オーナーが2026-09-12にF28と同じ運用判断を下した**ので、その決定を同じ形で記録する。

## 決定

**プロキシ5社（FROM JAPAN/Jauce/Buyee/ZenMarket/Neokyo）の宅配便（FedEx/DHL/UPS）の表示送料には、
宅配業者側の遠隔地サーチャージがすでに含まれているものとして扱う。`compare.ts` 側で遠隔地
サーチャージを追加で乗せる処理はしない（現状の「何もしない」を維持）。リスクとして登録する。**

記録先: `master/carrier-surcharges.json` の `conclusions.remote_area_surcharge_working_treatment`
（id: `C12_remote_area_working_treatment_2026_09_12`）。`confidence` は F28 と同じ
`reasoned_judgement_unconfirmed`（`direct_fetch` でも `search_snippet` でもない。事実の取得経路
ではなく、事実が未確認のまま下した判断の確度を表す新設語彙）。**これは事実の確認ではなく判断の
記録であり、事実として「遠隔地サーチャージは込みである」と主張するものではない。**

`compare.ts` は現時点で遠隔地サーチャージの処理を一切持たないため、この判断がどちらに転んでも
2026-09-12時点の出力額は変わらない。変わるのは記録であって、表示金額ではない（購入は行っていない）。

## 根拠（F28と共有する部分）

- プロキシは宅配業者から見て自らがアカウント保有者であり、我々（プロキシの顧客）へは単一の
  最終価格を提示する構造である。宅配便計測値（`master/courier-rates.json`）は
  `MeasuredPostageRate`——プロキシ自身の計算機が返す最終価格であり、日本郵便のように基礎料金へ
  こちらでマークアップ率を掛けて再構成するモデルではない。したがって、この最終価格に遠隔地
  サーチャージを別途加算する処理を書くと、もし最終価格が既にそれを含んでいた場合は二重計上に
  なる。この構造はF28の理由（G1・G2）とまったく同じである。
- FedEx/DHL/UPSのいずれも、遠隔地サーチャージが表示運賃に含まれるか否かを明言する一次記述は、
  `master/carrier-surcharges.json` の既存測定（C6・C9）の範囲では見当たらなかった。燃油の場合
  （C11のG7）と同じ「どちらとも書かれていない」状態であり、これは「含まれない」ことの証拠には
  ならない（原則2）。

## 反論（F28とは異なる、真剣に扱うべき非対称性）

**燃油サーチャージと遠隔地サーチャージには決定的な違いがある。燃油は全ての出荷に一律で乗る率だが、
遠隔地サーチャージは宛先住所（郵便番号）が宅配業者の遠隔地リストに該当する場合にのみ発生する。**

`master/carrier-surcharges.json` の既存の結論 `C4_remote_area_not_evaluable_in_product` が
既に指摘している通り、本マスタの宅配便計測（`master/courier-rates.json`）は国ごとに単一の
郵便番号でしか捕獲しておらず、その郵便番号が遠隔地リストに該当するかどうかは確認していない。

この非対称性が意味すること:

- 捕獲に使った郵便番号が遠隔地に**該当しない**（都市部の）ものであれば、その見積りには
  遠隔地サーチャージが含まれる余地自体が最初から無い。この場合、「加算しない」という
  判断はそもそも二重計上のリスクを生まない（正しい）。
- しかし、実際の利用者の宛先が**遠隔地に該当する**場合、「込みと仮定して加算しない」という
  今回の判断のせいで、本マスタの見積りは遠隔地サーチャージ分だけ**低く出続ける**。

つまり、この判断が誤っている場合の効き方は、燃油の場合（誤っていれば過大表示になる、という
対称的なリスク）とは異なり、**過小表示という一方向のリスクである。** F40 の row が
`master/fees.json` で `kind: "carrier_attribute"` として現に F28 と同じ扱いにまとめられている
一方で、この非対称性は F28 と F40 をいずれ別の扱いに分けるべきかもしれない、という**開かれた
問い**として残す。現時点では、オーナーの判断により両者を同じ working_treatment で揃えているが、
これは「両者の性質が同じだから」ではなく「どちらも一次情報で二重計上の有無を確認できていない
ので、暫定的に同じ簡便な扱いにしておく」という運用上の選択である。

## 決着させる実験

同一のカート内容・同一の箱サイズで、同じ国・同じプロキシ・同じ日に、次の2条件を見積り、
表示された全方式の `price_jpy` と `methods_shown_total`（原則2により必須）を記録して比較する:

- (a) 宅配業者自身の遠隔地リストに該当する**既知の遠隔地宛て郵便番号**
- (b) 該当しない**大都市圏の郵便番号**（既存データの基準点でよい）

**判定規則**: (a)と(b)で価格差が出れば、その差額が公表されている遠隔地サーチャージ額と整合する
かを確認する。差が出なければ、遠隔地サーチャージが表示価格に反映されていない（または該当判定
自体が機能していない）ことを疑う。

**具体的な郵便番号を確立できたか**: 確立できていない。`C9_fedex_remote_area_amounts_found_tier_list_still_missing`
が記録する通り、2026-09-12にFedEx日本発ODA/OPAの金額（レベルA/B/C）はPDFから取得できたが、
郵便番号→レベル該当のマッピング表は別のXLSXファイル（URLパスに`us-united-states`を含み、
米国宛て限定の可能性が高い）にあるとみられ、まだ開いていない。日本以外の6か国向けの区分
リストも見つかっていない。DHLについては「遠隔地配達手数料」ページの存在のみ（C6のjp-ja FAQ）
を確認しており、各国の遠隔地郵便番号リストの所在URLはまだ探せていない。**次の一歩**は、
(1) 上記FedEx XLSXを開いて米国の遠隔地郵便番号を1件抽出する、または (2) DHLの遠隔地ページから
各国の遠隔地郵便番号リストを探す、のいずれかである。したがって上記(a)の具体的な郵便番号は
本エントリの時点では未確定のまま残す。

## 両者を貫くリスク（F28とF40が共倒れになる可能性）

F28（`C11_fuel_working_treatment_2026_09_12`）とF40（`C12_remote_area_working_treatment_2026_09_12`）
は、同じ未検証の前提——**「プロキシの最終表示価格は宅配業者側の可変サーチャージを織り込み済み
である」**——の上に立っている。もしこの前提が誤っていれば、燃油と遠隔地の両方が同時に、
同じ方向（本マスタの見積りが実際より低く出る）に誤ることになる。**片方だけを検証して他方を
安全とみなすことはできない**——両者は独立した検証ではなく、同じ仮定の2つの表れである。
これはプロジェクトのリスクとして両エントリ（`master/carrier-surcharges.json` の
`conclusions.fuel_surcharge_working_treatment.cross_reference` と
`conclusions.remote_area_surcharge_working_treatment.shared_premise_risk_with_fuel`）から
相互参照している。
