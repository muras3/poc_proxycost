## P2 ── 宅配便を価格化する（金額の効きが最大）

| # | やること |
|---|---|
| 2a | `Item`／個口に**寸法の軸**を足す（箱を仮定する。梱包後重量を `×1.2+300g` と仮定しているのと同じ性質） |
| 2b | ZenMarket の見積 API で境界値を取り、**容積重量の除数**を決める |
| 2c | F28／F40 燃油・遠隔地サーチャージ（**送料の 2〜3 割**） |
| 2d | F34 通関手数料に**業者の軸**（経路で €1.56〜€70 = 45倍） |
| 2e | 方式セレクタ ＋ 即時再ランキング |

実請求の言及数は **FedEx 12 / EMS 11 / UPS 7 / DHL 7 / 船便 3**。
**発送の約半数が宅配便なのに、そこに 1 円も出していない。**
スペインの同一荷物の見積では船便 €27 ／ FedEx €40 ／ UPS €55 ／ DHL €61 ／ EMS €63 で、
**送料だけで 2.3 倍・差 €36 ≒ ¥5,900** ── 会社間の最大差（5点で ¥5,250）を超える。

外部文書 D3「比較単位は `Proxy × Shipping Method`」が完成するのはここ。

**2a〜2d は切り離せない。**送料だけ入れて通関を郵便のまま置くと、
**送料は下がり通関は上がるという向きが逆の誤りが総額に同居する。**

## 依存関係の要点

- **0a が全部の前提。**これが無いと、P2 の最中にマスタの取得済みデータを見落とす
- **P1 → P2 の順。**逆にすると、宅配便で増えた未取得費目がまた 0 に落ちる
- **3a と 4c は同じ作業で取れる。**O3 実行で申告額と実請求を同時に取る。分けると2回アカウントを作ることになる
- **P5 は独立。**比較エンジンに触らない
