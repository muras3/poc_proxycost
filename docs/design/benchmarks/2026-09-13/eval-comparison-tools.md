  - **右側に内訳サマリーを固定表示**: 選んだ代行について「商品代 / 代行手数料 / 国際送料 / 関税等（見込み） / 合計」を縦に並べ、合計だけ太字。行を選ぶと入れ替わる形は、desktop の proxycost の詳細パネルに合う。

## s15 Wise compare — 参考度 5（最重要）
- 第一印象: 濃い森のような緑の地に、ライムグリーンの極太コンデンス大文字見出し。表のカードは白で角が大きく丸い。表の見出し行は濃い緑、数値は落ち着いたサンセリフ。ブランドの主張は強いが、表の中は静かで密度が高い。
- 比較・ランキング・手数料の見せ方（切り出した画像で確認）:
  - 表の上に入力: 通貨ペアのセレクト2つ（⇄ で入れ替え）と「You send exactly 1,000 GBP」。左には基準の中値レート「1 GBP = 1.16625 EUR」と「less than a minute ago」（データの鮮度）を表示。
  - 列は「Provider / Exchange rate / Transfer fee / Recipient gets」。**一番右が受取額（＝手数料込みの結果）で、これが並び順の基準**。太字で最も大きく出している。
  - 1位（自社）以外の行は、受取額の下に**赤字で 1位との差額**（−6.37 EUR、−21.41 …）を出す。順位の間隔が数字で直感的に分かる。
  - レートの横に小さな赤丸（中値より悪い）と緑丸（中値）。手数料が 0.00 GBP でもレートの上乗せで負ける、という**隠れコストの構造が見て分かる**。
  - 「[?]」の注記（Mid-market rate / Transparent fee）と、一部の行に ⚠ アイコン（条件付きの意味と思われるが、中身は画像からは読めない）。
  - 表の下に前提条件「The above information applies when you pay in via bank transfer」と「How do we collect these data?」のリンク。
  - mobile の fold は大見出しとボタン2つで画面が埋まり、表が見えるのは下にスクロールしてから。
- 取り入れる点:
  1. **並び順の基準列を右端に置き、太字で最大にする**: proxycost の「玄関到着総額（円／現地通貨）」をこの位置にし、行の並びと一致させる。
  2. **1位との差額を行ごとに副表示**: 「+¥1,240」を小さな赤字で総額の下に。5社しかないので差額が一番効く情報になる。
  3. **中間の列は総額を分解した内訳列にする**: 代行手数料・国内送料・国際送料・関税等の見込みを列にし、「0円でも総額では負ける」が見て分かる構成にする。
  4. **1マスごとの確度マーク**: Wise の赤丸・緑丸の考え方を、proxycost の「公表の料金表／推定／二次情報」の3段階に転用する（色だけに頼らず、形か文字も付ける）。
  5. **表の直下に前提と「データの集め方」リンク**: 「支払い方法・配送方法・重量○kg の場合」と、根拠ページ（/sources）への導線。
  6. 入力の横に**鮮度表示**（「料金表 2026-09-01 確認」など）。
- 避ける点: 自社を1位に固定し「Send money」ボタンを付けている＝中立ではない（proxycost は中立に並べることが価値そのもの）。mobile のヒーローが大きすぎて表が画面外に落ちている。モバイル表示で横4列の表をどう崩しているかは、この画像からは判断しきれない。

## 比較 UI の共通パターン（見えた範囲から）
- **並び順の基準は「受け取る側から見た最終的な数値」を1つだけにする**（Wise と Monito の Recipient gets）。レートや手数料は、その理由を説明する補助列。
- 入力は**1枚のカードに、ラベル付きで横に並べる**（from/to ⇄ 入れ替え、金額＋単位）。結果は入力のすぐ下。
- **1位を強調**（色付きの帯・枠・ボタン）し、2位以下は同じ形式のリストで淡々と並べる。
- **1位との差を数字で出す**（Wise の赤字の差額）。
- 数値の算定方法は **ⓘ / [?] の注記**と、表の下の「データの集め方」リンクで説明する。
- 前提条件（支払い方法・通貨）と**データの鮮度**を表の近くに明記する。
- 「Best for 〜」のような**用途別の一言タグ**。
- 悪い共通点: 自社や広告主を優先する表示、Cookie モーダルやヒーローで表が画面外に押し出される、mobile 表の横はみ出し。

## proxycost が真似すべきトップ5
1. **Wise 型の「総額列を右端・太字・並び順の基準」＋行ごとの「1位との差額（+¥）」**。5社の順位の間隔が一目で分かる。
2. **内訳を列に分けて、1マスごとに確度マークを付ける**（Wise の赤丸・緑丸を「公表の料金表／推定／二次情報」の3段階に転用。色＋形／文字で）。「手数料 0円でも総額では負ける」が見て分かる。
3. **mobile は Monito 型の「ベストな選択カード＋残り4社のコンパクトなリスト」**。総額の横に確度と所要日数の副表示、「内訳」ボタンで展開。
4. **表の直下に前提条件・鮮度・根拠へのリンク**（「重量 1.2kg（推定）・EMS・カード払いの場合／料金表 2026-09-01 確認／データの集め方 → /sources」）。
5. **入力は1枚のカードに、ラベルを上に置いて横に並べる**（Monito / Google Flights 型: 商品・届け先の国・配送方法・通貨）。結果を fold 内に収めるため、ヒーローは最小限にする。加えて、中立性を守るため自社優遇のような表示や「Special offer」系のタグは入れない。

- 補足（撮り直し分から）: Easyship の「最安 / 最速 / バランス」ラベルと右側の内訳サマリー、NerdWallet の「最終更新日＋検証バッジ＋広告の開示」をヘッダーに置く形も、それぞれ 3 と 4 を補強する。

## 再撮影の提案
Parcel Monkey / Skyscanner は撮り直しても取得不可。NerdWallet と PriceRunner は desktop が遮断されたまま。Easyship は計算機本体が未撮影、Zonos は計算機部分の描画失敗。Google Flights と Monito は**検索結果ページ**を撮らないと、結果一覧 UI の評価が不十分なまま。
