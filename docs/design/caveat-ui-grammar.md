# 注意事項の視覚の文法（caveat UI grammar）— 設計判断 2026-09-15

前提: `docs/design/caveat-coverage-audit.md` の 100 件（結果 19・行 27・費目 34・画面固定 20）が対象。オーナーの要求は「最高に見やすい」×「言葉でなくUIで伝える」。見本は `prototypes/caveat-grammar.html`。`docs/design/caveat-tiers.md`（48件・3段階）はこの2文書に置き換える。

## 0. 結論を先に

**7つの手段に7つの意味。1つの手段は1つの意味しか持たず、1つの意味は1つの手段でしか表さない。**

| 手段 | 意味（これだけ） | 具体 |
|---|---|---|
| **位置**（縦の場所） | いつ読むべきか＝決定への効き方 | 段1: ボードの上の条件帯（最大 1 行 ＋ 常時帯 1 行）。段2: 数字そのもの。段3: 行を開いた配達ログ。**順位に入らない行は罫線の下** |
| **線種**（金額の下線） | その数字の出どころ | 実線＝公表値／破線＝当方の推定／点線＝二次情報／線なし＝総額に入っていない |
| **数字の書き方** | その数字の形（幅・上端・精度） | `¥a – b`＝幅と上端が分かる／`¥a+`＝上端が置けない／総額は ¥100 丸め・差額は円単位／差額に `≥`＝下限でしかない。**`≈`（`~`）は廃止**（§2.1） |
| **区間の帯**（行ごとの横棒） | 総額がどこからどこまで伸びうるか、1位と重なるか | 1位の下端を 0 とした共通の軸に `[low, high]` を棒で描く。上端が無い棒は右端をぼかす（Correll & Gleicher 2014 の gradient plot）。1位の帯と重なる行は同じ縦ブラケットで括る |
| **記号**（3つだけ） | `!`＝決定が変わる事実がある／`?`＝数字を持っていない（仮置き）／`§`＝根拠が読める | `!` は赤枠、`?` は赤の丸、`§` は藍の小さな四角。それ以外の記号（⚠ ↔ ★ ✎ ···）は使わない |
| **状態**（無効・順位外・薄さ） | 比べていない・選べない | 順位外の行: 順位番号無し・総額 `—`・灰色・罫線の下。選べない方式: `disabled` ＋理由。仮置きの箱の中身: 点線の輪郭 |
| **動き**（2つだけ） | 「順位が入れ替わった」「1位が決まった」 | 行の滑り（FLIP 260 ms）とスタンプの押印。それ以外は動かさない（`prefers-reduced-motion` で両方止める） |

色は **赤（`!`・1位のスタンプ・`?`）と藍（推定の線と `§`）の2色**だけを意味に使う。灰は「順位外」の状態にだけ。緑は使わない（「安全」を意味しないため）。

## 2. なぜそう決めたか

### 2.1 `≈`／`~` をやめる
エンジンの `Row.approximate` は 15,621 条件の全 comparable 行で真だった（関税の estimate と入金手数料の estimate が必ず残る）。全行に付く印は区別を作らない。van der Bles et al. (2020, PNAS 117(14):7672) は、数値の不確かさは**幅（数値レンジ）で示すと信頼をほとんど落とさず、言葉で示すと落ちる**と報告している。幅（`¥a – b`）と線種が既に推定を運んでいるので、`≈` は二重。

### 2.2 幅は棒で、上端不明はぼかしで
MacEachren et al. (2012, IEEE TVCG 18(12):2496) は不確かさの視覚変数として **fuzziness（ぼかし）と location（位置）**が最も直感的に読まれ、色相・形は弱いと実験で示した。Correll & Gleicher (2014, IEEE TVCG 20(12):2142) はエラーバーが「バーの内側は確からしい／外側は無い」と誤読させ、**gradient plot**がその誤読を減らすと示した。総額の区間を「1位の下端を原点にした共通軸の棒」で描き、上端不明の棒の右端をグラデーションで消すのはこの2つから。Kay et al. (2016, CHI, quantile dotplot) は小画面で確率を点の数で数えさせる案だが、こちらの不確かさは分布ではなく区間（下端は確か・上端は不明）なので採らない。Hullman et al. (2019, IEEE TVCG 25(1):903) は不確かさ表示の評価が「正しい行動」を定義してから測るべきだと言う—ここでの正しい行動は「1位の帯に重なる社を同格に扱う」で、ブラケットがそれを直接描く。

### 2.3 `!` は1画面に少なく
Akhawe & Felt (2013, USENIX Security) はブラウザ警告 2,500 万件で、警告の頻度と種類でクリックスルー率が 10%〜70% まで割れることを示した（同じ形の警告を常時出すと無視される）。常時帯（#82/#86）は `!` を付けず、`!` は**条件が成立したときだけ**、条件帯に 1 行・行に 1 行まで。ゆえに `RestrictedGoodsNote` の常時文から `!` を外し、GB/DE の電池だけ `!` にする。

### 2.4 `§` は根拠、判断材料ではない
NN/g の progressive disclosure（Nielsen, nngroup.com/articles/progressive-disclosure/）は「主要な選択肢だけを既定で見せ、副次を要求時に」。ここで副次＝**根拠**（出典・式・仮定の文）で、**決定を変える事実は副次にしない**。NN/g のツールチップ指針（nngroup.com/articles/tooltip-guidelines/）は「重要な情報をツールチップに入れない」と要約されることが多いが、**この記事の本文は今回確認できていない（未確認）**。

### 2.5 色だけに頼らない
WCAG 2.1 SC 1.4.1（w3.org/WAI/WCAG21/Understanding/use-of-color.html）: 色を唯一の手段にしない。線種・記号・位置がそれぞれ色無しで意味を運ぶ。赤の `!` は枠の形、藍の `§` は四角、`?` は丸。

## 3. 見やすさの制約（検査可能な形で）

| 制約 | 値 | 根拠 |
|---|---|---|
| 1行（1社）に常時出る記号 | **`!` 最大 1、`§` 最大 1、`?` 0**（`?` はカートだけ） | Mock 実測で `!` が行に 2 つ出た（Buyee default: 同梱＋追跡無し）。追跡無しを語に戻して 1 に |
| 同時に目に入る強い色 | **赤 2 か所以内**（1位のスタンプ＋条件帯の `!`）、藍は本数に上限を設けない（線であり面ではない） | Mock 初期状態は赤の要素 11〜18 個（Playwright 計測）。多すぎる |
| 段1が埋もれない | 条件帯はボードの直上、行の高さより大きい 1 枚。上に置ける文は 1 行＋常時帯 1 行 | `Calculator.tsx` の 908 > 900 px 事故（ボードが初期画面から押し出された）を繰り返さない |
| 390 px | 行は 3 段（社名・帯・総額）。区間の帯は幅 100% で描け、列を落とさない。横スクロール無し | Mock 26 シナリオで横スクロール 0 を維持 |
| 色に頼らない | 線種・形・位置の3つが色を外しても残る | WCAG 1.4.1 |
| 文の総量 | 条件帯 1 行 ≤ 90 字、行の `!` ≤ 60 字 | 折り返しで段1が2行になると初期画面を割る |

## 4. Mock でやめるべき表現（具体）

1. **`≈` 接頭辞**（全行・全費目・要約）。常に真なので情報が無い。線種と幅に任せる。
2. **`.band` の `!`**（"Not checked: whether your items…"）。常時出る警告は警告疲れの原因。`!` は条件が立ったときだけ（GB/DE の電池・酒・長物）。
3. **バッジ 3 種**（"Top pick"／"Top pick · either of two"／"As cheap, within error"）。同じ意味（1位の幅に重なる）を 3 語で言い分けている。ブラケット 1 本に。
4. **"OVER LIMIT" の赤・点滅**。分割できた箱に「超過」と書く意味の変化（監査 §3-6）。区切り線の線種で。
5. **Ships by 列の宅配便の日数に確度が無い**（"3-5 days" を郵便と同じ顔）。点線か `—`。
6. **フラップ文字のスクランブル**（`runFlaps`）。動きの意味は「順位が入れ替わった」だけにする。数字が回るのは「値が変わった」を示すが、行の滑りと二重で、reduced-motion でしか止まらない。
7. **`+` だけで済ませた漏れ費目**（監査 §3-4）。名前を行に戻す。
8. **"N of M services can't be ranked"** の行数／社数の取り違え（監査 §3-12）。数えるなら社で。
9. **`.band` の品目の決め打ち文**（"banned goods, batteries, liquids"）。`restrictedList()` から。
10. **`?` 付き仮置きの注記をカートを開いたときだけ出す**（監査 §3-11）。畳んだ見出しの隣に `?` と数。
11. 折り畳み **What could be off の "Not included"** は行の費目名と重複。削る。
12. **"the top-pick set changes in between"** の括弧書き。両端の枠の集合を書けば括弧は要らない。
